# 国会答弁・所管省庁ナビ

質問案を入力すると、国立国会図書館の国会会議録検索APIで関連する答弁発言を検索し、答弁者の肩書きを省庁に対応づけます。公開画面では取得した答弁発言の省庁別内訳を割合で表示します。

## できること

- 質問案から関連する国会会議録を検索する
- 発言単位の検索で政府側答弁を拾い、答弁者の肩書きを省庁ラベルに変換する
- 複数の政策語がある場合は同じ答弁発言に両方を含む結果を優先する（候補が少ないときは単語検索に戻す）
- 検索で得た答弁の内訳から候補割合と根拠発言へのリンクを返す
- e-Gov法令APIで各省の現行組織令に政策語の直接記載がある場合は、その法令へのリンクを別枠で表示する
- 会議録から `質問 → 答弁者 → 省庁ラベル` の教師データをJSONL/CSVで作る
- 作成した教師データで簡易分類器を評価する

## ローカル起動

Python 3で `python server.py` を実行し、http://127.0.0.1:8765 を開いてください。追加パッケージは不要です。外部通信ができる環境が必要です。質問全文は外部送信せず、抽出した検索語だけを国会図書館に送ります。

## 公開ページ

GitHub Pagesで公開する場合のURL:

https://yagiharuka.github.io/kokkai-ministry-router/

GitHub Pagesの画面は静的なままです。公開画面の更新には `.github/workflows/pages.yml` が `dist/` を配備します。ブラウザーのCORS制限を避けるため、会議録の取得だけを読み取り専用の中継APIに送ります。質問全文は送らず、抽出した検索語だけを国会図書館に転送します。公開中の読み取り専用中継APIは `https://kokkai-pages-api.haru620328.chatgpt.site/api/speech` です。

## 教師データを作る

まずは省庁ごとに出やすい政策語で会議録を集めます。国立国会図書館APIへの負荷を避けるため、検索は直列で数秒間隔を空けます。

```sh
bash scripts/collect_dataset.sh
```

直接指定する場合は次の形です。

```sh
python -m router.ministry_router collect \
  --keyword "半導体" \
  --keyword "医療機器" \
  --keyword "労働" \
  --limit 20 \
  --out data/labeled_pairs.jsonl
```

CSVにしたい場合:

```sh
python -m router.ministry_router csv \
  --data data/labeled_pairs.jsonl \
  --out data/labeled_pairs.csv
```

## 割合を予測する

作った教師データを使って、質問案に近い省庁を割合で返します。

```sh
python -m router.ministry_router predict \
  --data data/labeled_pairs.jsonl \
  "医療機器の国内開発を促進するため、研究開発支援と薬事承認の迅速化をどう進めるのか。"
```

出力には `shares` と `evidence` が含まれます。`shares` は省庁別の候補割合、`evidence` は判断に使った過去質疑です。

## 精度を見る

簡易的にデータを訓練用・検証用に分け、トップ1が正解省庁と一致した割合を出します。

```sh
bash scripts/evaluate_dataset.sh
```

## 解釈上の注意

公開画面の割合は検索結果に含まれる答弁発言の分布であり、校正済みの将来予測確率ではありません。組織令の一致は所管の補強材料であり、個別事業名が条文に載るとは限りません。議題が広い場合には、別の文脈で政策語に言及した発言が混ざることがあります。答弁者の役職が「国務大臣」のみの場合や、質問が複数発言にまたがる場合など、抽出できないことがあります。正式な所管の確認には担当部局の判断が必要です。

## 次の改善候補

- 検索語を手作業ではなく、省庁別の政策語リストから広く展開する
- 「国務大臣」のみの肩書きを、発言者名と当時の閣僚名簿で補完する
- 複数省庁が続けて答弁した場合をマルチラベルとして評価する
- 年度・委員会・会議種別で訓練データと評価データを分け、過学習を見つける
- TF-IDF/BM25や埋め込みモデルを導入し、現在の素朴な重みづけと比較する


## MCPエージェント

`mcp_server.py` は、会話型エージェントが国会会議録を検索するためのMCPサーバーです。LLMが質問案から検索語を選び、ツールがNDL APIから答弁候補を取得します。エージェントが質問との意味上の関連性を確認してから、省庁別の構成比と根拠を回答します。キーワードと省庁の固定対応表から担当を推測しません。

### ローカル接続

Python 3.10以上で `python -m pip install -r requirements-mcp.txt` を実行します。MCPクライアントからstdioで起動するコマンドは `python mcp_server.py`、作業ディレクトリはこのリポジトリです。エージェントの手順は `AGENT.md` にあります。

リモート接続用には `MCP_TRANSPORT=streamable-http python mcp_server.py` で起動できます。MCPクライアントから使うにはHTTPSで到達できる場所への別途ホストが必要です。GitHub Pagesは静的ファイル配信先なので、MCPサーバー自体はホストしません。

MCPツールはNDL APIの呼び出しを直列化し、数秒の間隔を空けます。APIエラーや関連事例なしの場合、割合を推測で埋めません。


### エージェント接続用の実行環境

GitHub Pagesの公開画面はそのまま利用します。ChatGPTから呼ぶMCP接続先には、依存パッケージ不要のWorker実装を [`mcp-worker/`](mcp-worker/) に用意しました。ChatGPT側で使うMCPツールは公開画面と別に稼働しています。会話モデルが答弁の文脈を判断できますが、GitHub Pages画面自体には会話モデルを搭載していません。
