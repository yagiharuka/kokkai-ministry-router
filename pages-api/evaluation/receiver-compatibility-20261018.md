# 初回AI判定の受信互換性（2026-10-18）

## 目的

使用しない引用欄を省略した明示的な不採用・保留を、形式エラーにして再検索を誘発しない。PR #5から受け取り側だけを分離する。AIへのプロンプト変更・省略形式の指示・出力スキーマ変更は取り込まない。

最大24候補、8件×3初回要求、追加確認上限、モデル、推論設定、入力原文、引用照合、課金設定、API要求は変更しない。公開版の意味契約はv79のままで、実装はコミットで識別する。

## 変更

明示的な reject/uncertain で、ID・受益者・活動・対象分類・比較理由・採否の6項目が文字列としてそろい、不明な追加項目がないときだけ、欠けたq/aを空文字として扱う。acceptの引用・欠落した意味項目・空の理由・未知の採否は補完しない。不採用を採用に変更しない。

追加のvalidation_failuresは固定のキーに対する件数だけで、原文・ユーザー質問・プロバイダの生応答・任意のフィールド名や値は含めない。未完了が引用欠落・理由欠落・未知の形式等のどれに当たるかを後から区別できる。回復件数はomitted_unused_refsで記録する。これらは生成AI呼び出しを追加しない。

完全に検証済みのバッチだけを保存する従来条件を維持する。省略欄を補完したキャッシュは従来の8項目形式に正規化し、旧実装へ戻した場合も読めるようにする。生のAI応答は変更しない。判断保留・架空の原文番号・不完全なバッチは保存しない。
