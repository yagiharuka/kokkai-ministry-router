## 再現した問題と変更

1. 採用根拠の質問・答弁番号が候補の原文辞書に存在しない場合、従来も割合には入れず保留していた。しかし、その行を判定完了として数え、全体を正常完了の24時間キャッシュへ保存する場合があった。今回は原文番号不整合を完了数から除き、固定カウンタ `unknown_accepted_refs` で記録する。他の正常な採否・引用・所属・候補順は変えない。モデルが正しく返した意味上の保留は、従来どおり判定完了に数える。
2. REST呼び出しの通信失敗をJSON不正と取り違えていた。通信・タイムアウトと応答形式の不正を分け、提供元の生メッセージを公開しない。モデルの呼び直しは増やさない。
3. 実機計測スクリプトが旧JSON-schema専用の項目を参照し、正常なJSON-object応答を計測処理自体の例外で失敗にしていた。PR #5の計測修正を現行mainから分離し、観測処理の失敗は元のHTTP応答を壊さないようにする。一部失敗したら後続の質問を試さない。
4. iPhoneでも使える既存の診断コピーに、すでに応答に含まれる検証失敗の件数、各判定の開始位置、検索・AI・合計時間を追加した。質問・答弁・モデルの生応答・認証情報は含めない。コピーのための通信は追加しない。

不完全な分析はHTTPでも `no-store` とする。旧版の誤った正常完了キャッシュを引き継がないよう、APIと画面を版80にそろえる。正常な意味判定バッチのキャッシュキーは公開版から独立しているため、入力・指示・モデル等が同一なら引き続き再利用できる。
