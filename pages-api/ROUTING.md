# 判定処理（2026-10-09）

政策名ごとの省庁辞書は使わない。質問案ごとに会議録を探し、質問と答弁を文脈で確認してから実際の答弁者の所属を集計する。

1. 公開サイトは質問全文を送る。モデル接続時には対象・制度・求める措置を読んで検索語と自然な言い換えを生成する。省庁名を推測して検索条件にしない。前の質問やモデルの会話履歴は再利用しない。
2. 国会会議録APIで直近3年を年ごとに検索し、その後で会議全体を取得する。質問や政府答弁の部分一致から候補を拾う。候補取得では全語一致や要求する動詞の一致を必要としない。
3. 議員質問から次の議員質問までの政府答弁を対応させ、前後の文脈と原文URLを保持する。委員長の手続発言は除く。同じ省庁の反復答弁も、この時点では別々に残す。
4. モデルが質問案と候補の質問・答弁を読み、accept / reject / uncertain を返す。対象・措置・範囲を照合し、言い換えは認める。背景で語に触れただけの発言や、複数論点の別の問いへの答弁は除く。政府の賛否が提案と違っても、同じ政策課題への答弁なら採用できる。
5. モデルは候補ID、短い採否理由、原文の抜粋だけを返す。所属・発言・URL・割合を生成しない。未知のID、欠落・重複、余計な項目、原文に存在しない引用は検証で検出し、判定全体を集計しない。この検証だけで意味判断の正しさを保証するものではない。
6. 答弁者の肩書きから所属を読む。他省への言及と自分の所属は区別し、兼務が判別できなければ推測しない。同一質疑・同一省庁の反復をまとめ、一質疑に複数省庁が答えた場合は重みを均等に分けて構成比を算出する。
7. 設置法・組織令・組織規則は補助資料として表示する。法令の単語一致だけで所属や担当割合を変えない。

公開APIとMCPは同じ `routing-core.mjs` を使う。MCPを呼ぶChatGPTは `candidates` と `review_candidates` を読んで文脈判断を行う。公開APIでは `semantic-review.mjs` がモデルを呼ぶ。コアの文字一致による暫定割合は公開APIで必ず破棄し、文脈判定で採用された候補から再計算する。

## 現在の公開構成

公開中継の `worker/index.js` は会議録を取得するだけで、OpenAI APIを呼ばない。公開画面の「判定用の質疑をコピー」で、質問案・実際の質問と答弁・所属・原文URL・重複を除く集計指示をChatGPTへ渡す。文脈の判定は既存のChatGPTまたは国会答弁ナビで行う。未判定候補をこの画面で自動的に割合に変換しない。

以下のモデル接続処理は追加機能として準備したコードであり、現在の公開版には含めない。`worker/model-api.js` と `worker/semantic-review.mjs` はAPI設定後の切替用である。キーの承認・設定を済ませてから `node scripts/build-core.mjs --semantic` でモデル版を作り、保存・デプロイする。

## 接続設定と結果の状態

- `OPENAI_API_KEY` は中継側のSites環境変数にシークレットとして設定する。ブラウザー・GitHub・設定ファイルには置かない。
- `OPENAI_ROUTER_MODEL` は任意。既定は `gpt-4.1`。Responses APIとStructured Outputs対応モデルを指定する。
- 一検索あたりモデル最大2回、会議録API最大14要求、判定候補最大12件。モデル要求は各40秒でタイムアウトし、自動再試行しない。
- 同一質問は中継プロセス内で10分キャッシュする（失敗時30秒）。別の質問に前の結果を持ち越さない。同時実行数とキャッシュはプロセス内の制限で、全体の料金上限ではない。
- `assessment_status` は `reviewed`（判定完了）、`not_configured`（未接続）、`failed`（判定失敗）、`no_candidates`（今回の取得範囲に候補なし）。未接続・失敗時には候補を残すが割合を出さない。採用0件や判断保留は会議録が存在しないことを意味しない。
- `GET /api/status` は設定の有無と処理バージョンだけを返し、キーを返さない。

OpenAI Developersの `openai-platform-api-key` 手順で承認されたキーを設定してから、モデルを使う中継の保存済み版をデプロイする。コード作成とモック検証は、自動判定の本番稼働を意味しない。

## 検証と限界

`npm test` で抽出・発言の対応・兼務・反復・年別取得、モデル出力の検証・失敗時の挙動・公開リクエスト経路・表示状態を確認する。モデル接続テストは模擬応答であり、意味判断の精度評価ではない。`real-excerpts.json` は少数の原文URL付き確認例で、修正に使った例も含む。独立した代表評価や正答率推定には使えない。

検索件数・会議数・抜粋長に上限があり、候補に入らない発言は判定できない。割合は取得・確認した標本の内訳で、将来の担当になる確率ではない。モデル接続後には修正に使っていない複数分野の質問で、採否と担当の妥当性を別途検証する。

仕様は [国立国会図書館](https://kokkai.ndl.go.jp/api.html) と [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses) を参照する。
