# 判定処理（2026-10-09）

政策名ごとの省庁辞書は使わない。質問案ごとに会議録を探し、質問と答弁を文脈で確認してから実際の答弁者の所属を集計する。

1. 公開サイトは質問全文を送る。モデル接続時には対象・制度・求める措置を読んで検索語と自然な言い換えを生成する。省庁名を推測して検索条件にしない。前の質問やモデルの会話履歴は再利用しない。
2. 公開APIは直近3年をまとめて、自然な言い換え2通りで検索する。発言検索に含まれる本文を再利用し、発言番号が連続する範囲だけ質問と答弁を対応づける。欠番をまたいで後の答弁を前の質問に結び付けない。最も関連する会議は全文も取得し、検索語を繰り返さない答弁を補う。候補が少なければ2番目の会議も取得する。採用0件なら不採用理由を踏まえて一度だけ検索語を作り直し、2020年以降へ広げる。年別の網羅検索ではなく、上限のある候補検索である。
3. 議員質問から次の議員質問までの政府答弁を対応させ、前後の文脈と原文URLを保持する。委員長の手続発言は役職欄と発言冒頭の見出しで除く。会議の取得では実際の議員質問を優先し、総花的な大臣演説だけで枠が埋まらないようにする。同じ省庁の反復答弁も、この時点では別々に残す。
4. モデルが質問案と候補の質問・答弁を読み、accept / reject / uncertain を返す。対象・措置・範囲を照合し、言い換えは認める。対象地域が省略されていれば日本国内の施策を想定し、質問案に外交・海外展開・輸出・国際協力などの指定があればその範囲を優先する。背景で語に触れただけの発言や、複数論点の別の問いへの答弁は除く。政府の賛否が提案と違っても、同じ政策課題への答弁なら採用できる。
5. モデルは候補ID、短い採否理由、原文の抜粋だけを返す。所属・発言・URL・割合を生成しない。利用者の質問案と会議録の質問は別の項目名で渡す。未知のID、欠落・重複、余計な項目は判定全体を集計しない。原文に存在しない引用がある候補は判断保留とし、原文で確認できたほかの候補は維持する。この検証だけで意味判断の正しさを保証するものではない。
6. 答弁者の肩書きから所属を読む。他省への言及と自分の所属は区別し、兼務が判別できなければ推測しない。同一質疑・同一省庁の反復をまとめ、一質疑に複数省庁が答えた場合は重みを均等に分けて構成比を算出する。
7. 設置法・組織令・組織規則は補助資料として非同期で表示する。省庁の判定結果を法令待ちで止めず、前の質問で遅れて届いた法令が新しい結果に混ざらないよう識別する。法令の単語一致だけで所属や担当割合を変えない。

公開APIとMCPは同じ `routing-core.mjs` を使う。MCPを呼ぶChatGPTは `candidates` と `review_candidates` を読んで文脈判断を行う。公開APIでは `fast-retrieval.mjs` が検索回数を減らし、共通コアで発言を対応づけた後、`semantic-review.mjs` がモデルを呼ぶ。MCPの年別検索は従来のまま。コアの文字一致による暫定割合は公開APIで必ず破棄し、文脈判定で採用された候補から再計算する。

## 現在の公開構成

`npm run build` は `worker/model-api.js` と `worker/semantic-review.mjs` を含む自動判定版を作る。GitHub Pagesの画面から質問全文を受け、中継側で検索語を作成し、実際の会議録を取得して文脈を判定する。ブラウザーでAPIキーを扱わない。

接続障害や判断保留では取得済み候補を残し、未判定候補を割合に変換しない。訪問者にChatGPTへのコピーや端末内モデルの実行を要求しない。会議録の取得のみを行う旧中継 `worker/index.js` は予備として保持する。明示的に `npm run build -- --retrieval-only` を実行すると、モデルを呼ばない版を作れる。

## 接続設定と結果の状態

- 文脈判定はCloudflare Workers AIのFreeプラン専用。`CLOUDFLARE_ACCOUNT_ID`、シークレットの `CLOUDFLARE_API_TOKEN` と、契約を確認したうえで `CLOUDFLARE_WORKERS_PLAN=free` を中継サーバーに設定する。未接続時は即座に準備中を返す。
- モデルは `@cf/qwen/qwen3-30b-a3b-fp8` 固定。旧OpenAIキーや任意の有料モデルへの切替は受け付けない。設定と現状は [FREE-CLOUD.md](FREE-CLOUD.md) を参照する。
- 通常は検索計画1回と、最大12候補を6件ずつ最大2並列で判定する。会議録APIは1回の探索で最大4要求。採用0件の場合だけ追加検索を一度行い、全体でモデル最大6要求・会議録API最大8要求・判定候補最大24件に制限する。NDLへの通信は並列化せず、取得完了後3秒の間隔を維持する。モデル要求は各40秒でタイムアウトする。モデルエラーでは追加検索や再試行を行わない。検索計画の段階でAI無料枠の消費などが分かれば、会議録取得を始めず即時に失敗状態を返す。提供元の生エラーや残高の詳細は公開しない。
- 同一質問は中継プロセス内で10分キャッシュする（失敗時30秒）。取得済みの公開会議録は条件を厳密に照合して1時間キャッシュする（プロセス内12MiB・32件まで）。別の質問に前の判定を持ち越さない。同時実行数とキャッシュはプロセス内の制限。無料枠の超過はCloudflare側のFreeプランが停止する。
- `assessment_status` は `reviewed`（判定完了）、`not_configured`（未接続）、`failed`（判定失敗）、`no_candidates`（今回の取得範囲に候補なし）。未接続・失敗時には候補を残すが割合を出さない。採用0件や判断保留は会議録が存在しないことを意味しない。
- `GET /api/status` は設定の有無と処理バージョンだけを返し、キーを返さない。

旧有料APIのシークレットは公開環境から削除済み。環境変数を変更した際は保存済み版を再配備する。Cloudflareはまだ未接続であり、実際の判定精度と速度は未検証。

## 検証と限界

`npm test` で抽出・発言の対応・兼務・反復・年別取得、モデル出力の検証・失敗時の挙動・公開リクエスト経路・表示状態を確認する。モデル接続テストは模擬応答であり、意味判断の精度評価ではない。`real-excerpts.json` は少数の原文URL付き確認例で、修正に使った例も含む。独立した代表評価や正答率推定には使えない。

検索件数・会議数・抜粋長に上限があり、候補に入らない発言は判定できない。割合は取得・確認した標本の内訳で、将来の担当になる確率ではない。

`node scripts/evaluate-live.mjs` は設定済みのWorkers Freeと会議録を実際に呼ぶ手動検証。無料枠を消費し、失敗時には後続を止める。通常テストには含めない。例題は開発用で、独立した正答率評価ではない。

仕様は [国立国会図書館](https://kokkai.ndl.go.jp/api.html) と [Workers AI JSON mode](https://developers.cloudflare.com/workers-ai/features/json-mode/) を参照する。
