# 判定処理（2026-10-09）

政策名ごとの省庁辞書は使わない。会議録の質問と実際の答弁者を根拠にする。

1. 質問全文を文字正規化し、対象・制度・限定条件の概念を取り出す。一般的な依頼表現は共通に除く。公開画面は検索語だけでなく質問全文を API に送る。
2. 国会会議録の発言検索で候補を取得する。直近3年は1年ずつ検索し、直近年の検索上限100件によって前年の発言が隠れないようにする。対象・論点の双方から検索してから段階的に条件を広げるが、質問全文の関連性条件は保持する。検索語の言い換えは所管ラベルにはならない。
3. 発言全体を単語の袋として扱わず、文と論点の切り替わりで区切る。対象・論点の一致と取得候補内での語の希少性で質問候補を並べ直す。
4. 選んだ議員発言から次の議員発言までを答弁の候補とする。委員長の手続発言は数えない。答弁の該当部分が対象に対応している場合を採用する。質問中の周辺語で言い換えを補う場合も、元の質問の主要対象が答弁に残っていることを必要とする。
5. 答弁者の肩書きから所属を読む。他省への言及と自分の所属への明示は区別する。兼務が判別できない答弁は集計から外す。近くの同じ対象の答弁で立場が明示された場合は参照できる。
6. 同一質疑・同一省庁の反復をまとめる。一質疑に複数省庁が答えた場合は重みを均等に分ける。最近の記録が見つかれば古い所属と合算しない。

公開 API と MCP は同じ `routing-core.mjs` を使う。MCP を呼ぶモデルは、返された候補を読んで政策の目的・手段・対象の意味上の一致を確認し、適合する質疑だけを集計する必要がある。公開画面の関連性処理は文字・語の一致に基づき、汎用言語モデルで意味を推論しているわけではない。

## 検証

`node pages-api/scripts/test-routing.mjs` で、異なる対象、論点移動、質問と答弁の対応、兼務、重複、最近の記録の分離を検証する。`real-excerpts.json` は会議録への URL を持つ少数の確認例である。修正に使った事例も含むため、代表的な独立評価データや全体の正答率の推定には使えない。

## 限界

- 同じ対象の別施策、国内向けと国外向けの施策、語の一致が少ない言い換えには誤採用・取りこぼしが残る。意味を判断するモデルが公開画面の中継先に接続されていないため、「教員」と「教師」、「長時間労働」と「時間外在校等時間」などの表記違いはなお拾えない場合がある。
- 検索件数と取得会議数には上限がある。割合は確認した標本の答弁内訳であり、担当になる確率ではない。
- 設置法・組織令・組織規則の検索は補助資料であり、単語があるだけで答弁の所属を変更しない。
- 会議録 API への要求は処理内で直列化し、完了後に間隔を置く。仕様は [国立国会図書館の API 文書](https://kokkai.ndl.go.jp/api.html) を参照する。
